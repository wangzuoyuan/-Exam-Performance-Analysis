# 成绩分析（班主任版）— 升级换届与学情继承 · Plan 与执行蓝图

把现有「成绩分析 webapp」改造成**能跨学年换届的班主任版**：一位班主任带**一个行政班**，但
**高一→高二会分班**——班级号变、名册变、**学号也变**。改造目标是让「同一个学生」的成绩、
谈话/作业档案在换届后依然连贯，同时给新转入的学生从高二起建档（可选导入其高一成绩）。

> 本目录**只包含 plan 与执行蓝图**，不含代码改动。源工程在 `../成绩分析webapp`。
> 蓝图按文件拆分，建议按顺序阅读。

## 一句话核心

> 现系统把「同一个学生」**等同于一个 `student_id`**——高一→高二分班后学号变，
> 跨学年画像/趋势/档案就会**断裂**。
> 班主任版引入一层**「人（identity）」**，把「**学号（每学段一个）**」与「**人（跨学段）**」解耦；
> 再用一次性的**「升级换届向导」**，把高一名册结转到高二：逐个学生判定
> **继承 / 新建 / 离班 / 导入高一成绩**，建立「高一学号 ↔ 高二学号」链接。
> 单年分析（关注名单、段位、考试详情、班级对比）**完全不变**，仍按当年 `class_num`——零回归。

## 与「教学版」的关系（务必区分）

| | 教学版（`../成绩分析（教学版）`） | 班主任版（本目录） |
|---|---|---|
| 老师模型 | 一个老师带**多个教学班**（走班） | 一个班主任带**一个行政班** |
| 班级标识 | 引入字符串 `class_label`（`物A1`/`史B3`） | **不引入**，沿用单一行政班号 `target_class_highN` |
| 核心改造 | 把「按 `class_num` 过滤」升级为「按教学班成员集合过滤」 | **身份层 + 升级换届**，解决跨学年学号变更 |
| 身份层 | 06 文档作为附录提及 | **本版的主线**（贯穿 02/03/04） |

> 班主任版**复用**教学版 06 文档关于「身份层」的结论（`student_identity`/`student_alias`、
> 「姓名确认为主 + 对照表为辅」、`xueji` 不是身份键），但**剥离**走班/`class_label` 的全部复杂度，
> 改以「班主任单班换届」为中心重新组织。两版互不依赖，可独立实施。

## 已确认的关键决策（来自用户）

1. **产出**：只写计划与执行蓝图，输出到本目录，不改源码。
2. **身份接续**：**姓名确认为主 + 学号对照表为辅**；库里无稳定唯一字段可自动认人（`xueji` 是 1/3/4 状态码，非身份），**绝不**按姓名自动并档。
3. 班主任模型**保持单班**：每学段一个行政班（`target_class_highN`），不引入教学班抽象。
4. 单年分析口径不动：关注名单/段位/考试详情/对比仍按 `class_num`，只有「以学生为中心的跨学年视图」才解析身份。
5. 导入的高一成绩**仅供该生历史趋势**，隔离存储，**绝不**进入任何全年级排名/班均口径。
