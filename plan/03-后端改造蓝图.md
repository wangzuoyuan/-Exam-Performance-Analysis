# 03 · 后端改造蓝图

源：`backend/app/`。FastAPI 路由挂 `/api`。改造原则：**身份解析是叠加层，只在跨学年学生视图启用；单年分析一律不动。**

## 1. 新增核心模块 `analysis/identity.py`

跨学年身份解析，被学生视图端点与换届服务共用：

```python
def identity_of(db, student_id) -> int | None:
    """学号 → identity_id；无 alias 则 None（视为独立人）。"""

def person_ids(db, student_id) -> set[str]:
    """给定任一学号，返回同一人【全部学段学号】；无 alias 时返回 {student_id}。
    读侧统一用它把 `== student_id` 改成 `IN person_ids`。"""

def link_aliases(db, identity_id, items, source):
    """建立链接。items=[(student_id, grade), ...]；source ∈ name_confirmed/crosswalk/manual。
    若某 student_id 已属他人 → 报冲突，不静默覆盖。"""

def unlink_alias(db, student_id):
    """解除关联（删 alias），学号还原为独立人（01·D6）。"""

def ensure_identity(db, *, display_name, gender=None) -> int:
    """新建一个 identity，返回 id（新生建档 / 首次建链时用）。"""

def name_candidates(db, name, target_grade=1) -> list[dict]:
    """按姓名在 target_grade 的成绩记录里找候选人，返回
    [{student_id, class_num, latest_main_rank, latest_exam_name, already_linked}]，
    供向导逐人确认同名。数据源：SubjectScore.name（复用 homework/migrate 的姓名映射思路）。"""

def import_crosswalk(db, rows) -> dict:
    """导入「高一学号↔高二学号」对照表批量建链。
    rows=[{g1_sid, g2_sid, name?}]；返回 {linked, conflict, skipped}。"""
```

> **无「按字段自动并档」函数**——链接只来自老师确认或对照表导入（01·D2）。

## 2. 读侧改造：以学生为中心的端点按「人」并集（`analysis/router.py`）

> 通用规则：把 `TotalScore.student_id == student_id` / `SubjectScore.student_id == student_id`
> 替换为 `.in_(ids)`，其中 `ids = person_ids(db, student_id)`。**其余端点一律不碰。**

### 2.1 `GET /students/{id}`（画像 / 跨学年趋势 / 班级排名）— 主战场
现状（`router.py:605` 起）：所有 `TotalScore/SubjectScore` 查询都 `== student_id`，整段画像绑死单一学号。改造：

1. 入口先 `ids = person_ids(db, student_id)`；下列查询全部改 `.in_(ids)`：
   `exams`（join TotalScore）、`main_totals` / `five_totals` / `plus3_totals` / `san3_totals`、`subject_scores`、`name_row`。
2. **班级排名**（`class_rank_by_exam`）：现已是「按 `exam_id` 取该生当场 `class_num`，再在同班同考试 peer 里排名」——**逻辑天然正确**，union 后高一场用高一班、高二场用高二班，无需改算法，只是 `subject_scores` 现在含两个学号的行（按 `exam_id` 聚合不冲突）。
3. **头部班级**（现 `class_counter.most_common`）：改为「取**当前最高年级**那场的 `class_num`」，避免高一/高二班号混选。新增返回 `class_by_grade: {1: 6, 2: 3}` 供前端展示学段履历。
4. **并入导入的高一成绩**（`imported_history`）：`iid = identity_of(...)`，若有则把该 identity 的 `imported_history` 行转成趋势点，打 `imported: true`、`grade: 1`，按 `exam_sort_key` 一并排序后插入各 `*_trend`。前端用虚线/淡色区分（04·§2）。
5. 新增返回 `identity: {id, aliases: [{student_id, grade, class_num}]}`，供「学段履历」头部与「解除关联」。

### 2.2 学生页的档案 / 作业读取
- `notes/router.py` `GET /api/notes/{student_id}`：改 `student_id.in_(person_ids(...))`，使高一档案在高二画像可见（继承）。
- `homework/router.py` `GET /student/{student_id}`（学生作业概况）：同样按 `person_ids` 并集读，高一缺交历史在高二画像可见。
- > **但作业看板/排行/预警（单年统计）不变**：仍按当前 `active_grade` 名册、当年学号，不跨年混算（01·D4、02·§2）。

### 2.3 学生检索 `GET /api/students`（新增端点，替代前端低效聚合）
现状：前端对每场考试 `fetch /api/exams/{id}` 再本地聚合（班级越多越慢）。新增后端端点：
- 返回「我范围内的学生」列表，**按人去重**（同一人多学号合并一行，显示**当前学段学号 + 当前班级**，可展开历史学号）。
- 去重实现：先取候选学号集合 → 用 `identity_of` 归并到 identity → 每个 identity 输出一行（无 identity 的学号各自成行）。
- 每行附最近一场主三门成绩摘要。前端 `/student` 检索页改用此端点（04·§3）。

### 2.4 不解析身份的端点（**保持原样，零改动**）
`GET /exams/{id}`、`/focus-list/{id}`、`/subject-weakness/{id}`、`/band-trend`、`/class/compare`、
`/rank-range`、`/rank-frequency`、`/rank-metrics` —— 全部仍按 `class_num` / `target_class_highN`。
年级内学号稳定，无需身份层。

## 3. 升级换届 API（新增 `rollover/router.py`，挂 `/api/rollover`）

换届向导的后端。服务逻辑放 `rollover/service.py`（被 router 共用）。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET  | `/api/rollover/preview?grade=2&class_num=` | **核心**。给定高二目标班 + 名册来源，对每个高二学生返回四态分类（见 §3.1） |
| POST | `/api/rollover/roster` | 建/刷高二作业花名册：来源 `{from_scores: true}`（按 `class_num` 从高二成绩派生）或 `{rows:[{student_id,name,seat_no,gender}]}`（Excel/手工）；写 `class_roster(grade=2)` |
| POST | `/api/rollover/link` | 确认建链：`{g2_student_id, g1_student_id, name, gender}` → `ensure_identity` + `link_aliases(name_confirmed)` |
| POST | `/api/rollover/link-batch` | 一次提交多条确认结果（向导「全部确认」） |
| DELETE | `/api/rollover/link/{student_id}` | 解除关联（`unlink_alias`） |
| POST | `/api/rollover/crosswalk` | 上传/粘贴「高一学号↔高二学号」对照表 → `import_crosswalk`，返回 `{linked, conflict, skipped}` |
| POST | `/api/rollover/import-history` | 新生导入高一成绩：上传 Excel 或粘贴 → 写 `imported_history`（按 identity），可同时建链 |
| PATCH | `/api/rollover/active-grade` | 设 `homework_setting.active_grade`（切换作业看板的当前年级） |

### 3.1 `preview` 的四态判定逻辑（`rollover/service.classify`）
对高二名册的每个学生（来自高二成绩 `class_num==target` 或导入的花名册），按序判定：

1. **已建链** → `inherited`（含 `g1_student_id`、高一班号）。
2. 未建链 → `name_candidates(name, target_grade=1)`：
   - 恰好/存在高一候选 → `ambiguous`，附候选列表（高一行政班 / 最近主三门名次 / 高一学号）让老师选「是某某 / 是新学生」。
   - 唯一且老师在向导里直接确认 → 走 `/link` 落 `inherited`。
3. **零候选**：
   - 该学号在高二成绩库里有数据 → `new`（新学生，从高二起；附「导入高一成绩 / 手动关联高一学号」操作）。
   - 该学号仅来自花名册、成绩库无任何数据 → `unmatched`（待补：等高二成绩上传，或核对学号）。

> 返回结构：`{inherited:[...], ambiguous:[...], new:[...], unmatched:[...], summary:{counts}}`。
> **离班生**（高一在我班、高二名册里没有）单列 `left_class:[...]`，仅提示，无需动作——其高一数据保留，只是不在我高二名册。

### 3.2 姓名 → 学号反查（复用既有思路）
`name_candidates` 与 `import_crosswalk` 的姓名映射，**复用 `homework/migrate.py` 已验证的「按姓名映射到真实学号」逻辑**（`_grade_name_to_student_id`）：唯一命中直接落；同名多个进 `ambiguous` 待消歧；零命中进 `new/unmatched`。

## 4. init / 绑定流程微调（`main.py`）

- `POST /api/teacher/bind-class`（写 `target_class_highN`）**保留**——班主任版仍按行政班绑定。高二开学绑 `target_class_high2 = 新班号` 即触发「该去换届向导」的前端引导。
- 上传 `commit` 响应里的 `detected_class`：保留。新增逻辑——若检测到的年级 > 已绑定的最高年级（即首次出现高二数据），响应附 `suggest_rollover: true`，前端弹「检测到高二成绩，去做升级换届？」（04·§1）。
- `GET /api/teacher` 增派生字段 `has_pending_rollover`（存在高二成绩但身份层为空时为真），驱动首页横幅。

## 5. 对话工具（`chat/tools.py` + `chat/session.py`）

- **跨学年学生工具按人并集**：`student_lookup` / `student_trend` / `student_learning_profile` / `student_notes` / `student_homework_summary` 内部改用 `person_ids`，使 AI 谈到「某学生高一到高二的变化」时数据连贯。
- **单年班级工具不动**：`focus_list` / `subject_weakness` / `class_trend` / `compare_classes` / `band_trend` 等照旧按 `class_num`。
- `session.py` 系统提示补一句：「学生可能跨学年换过学号；以学生为中心的查询已自动合并同一人的多个学号；班级口径仍按当年行政班。」**业务口径（指标选择规则）原文保留。**
- 新增只读工具 `student_identity_lookup(name|student_id)`：返回某人的学段履历（高一/高二学号、班号、是否继承），供 AI 在「确认是不是同一人」时引用。
