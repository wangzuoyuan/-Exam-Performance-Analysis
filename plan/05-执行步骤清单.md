# 05 · 执行步骤清单（按顺序执行）

原则：**身份层是叠加层，先把它建好且默认退化为现状（零回归），再逐步在跨学年视图里点亮。**
建议从 `../成绩分析webapp` 起一个分支或复制工程再改。每阶段可独立验证、不破坏旧功能。

---

## Phase 0 · 准备与样本核对（半天）
- [ ] 复制 / 分支源工程为班主任版工作目录。
- [ ] **拿真实高二成绩样表**，确认：① 高二学号与高一是否真的不同段（A2）；② 班号列是高二行政班；③ `SELECT DISTINCT xueji` 复核它仍是 1/3/4 状态码、非身份键（A1）。
- [ ] 问学校教务**有没有「高一学号↔高二学号」对照表**（有则换届走辅路径，省大量逐人确认）。
- [ ] 确认转入生的高一成绩有无现成 Excel（决定 `import-history` 的输入格式）。

**里程碑 M0**：明确「学号确实变、无稳定唯一键、有无对照表」，据此定向导默认路径。

## 总工期估算
约 **8–9 个工作日**（单人）。关键路径：Phase 1→2→3→5。Phase 4 对话工具可后置。

> 比教学版（13–15 人日）轻：班主任版**不做**走班/`class_label`/多班 scope 的全系统改造，只加身份层 + 换届向导 + 少数学生视图改读侧，单年分析端点零改动。

## 风险与缓解
| 风险 | 影响 | 缓解 |
|------|------|------|
| 无对照表，全靠逐人姓名确认 | 换届初次成本高 | 同名 Dialog 附高一班/名次/学号辅助；沿班升年级时多数姓名唯一命中可批量确认；尽量争取教务对照表 |
| 同名学生反查歧义 | 错并档案 | `ambiguous` 强制人工消歧，**绝不**自动按姓名链接；错链可「解除关联」 |
| 导入的高一成绩污染全年级口径 | 排名/班均失真 | 隔离存 `imported_history`，**任何**全年级查询都不读它（02·§3） |
| 读侧 union 改动影响画像 | 跨学年趋势/排名错配 | 班级排名按当年 `class_num` peer（逻辑不变）；趋势点标注当年学段；配 `test_student_union` |
| 作业历史跨年混算 | 看板失真 | `class_roster.grade` + `active_grade`：看板单年，画像才并集 |

## 与源工程口径必须保持一致（勿改）
- 跨学年趋势指标规则、总分用 `xueji_rank`、+3 用等级分、`raw_score` 只作单点描述（源 `chat/session.py`）。
- 段位阈值统一读 `analysis/config.get_band_config()`，不硬编码；段位排名仍是**全年级**口径。
- 单年分析（关注名单/段位/考试详情/对比/排名筛选）一律按 `class_num`，不解析身份。
