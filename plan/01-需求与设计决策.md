# 01 · 需求与设计决策

## 1. 原始诉求拆解

| # | 原始诉求 | 落地含义 |
|---|----------|----------|
| 1 | 高一→高二可能**分班** | 班主任带的行政班，跨学年是「换届」——成员重组，不是同一批人原样升级 |
| 2 | **学生名册会变** | 高二名册 = 部分高一留任 + 部分新转入 − 部分离班；需要一次性「结转」工作流 |
| 3 | **学号会变** | 同一个人高一/高二两个学号；现系统按单一 `student_id` 聚合，跨学年画像会断裂 |
| 4 | **班级号会变** | 高二行政班号可能与高一不同；`target_class_high2` 单独设定 |
| 5 | 已有学生**成绩继承** + 新生**资料创建** | 留任生：高一成绩/档案接续到高二画像；新生：从高二起建档，可选导入其高一成绩 |

> 一句话：**事实（每场考试的分数）不变，变的是「谁是谁」**。改造就是补一层「人」，再用换届向导把高一/高二两个学号认成同一人。

## 2. 已确认决策（用户拍板）

### D1 · 保持「班主任单班」模型（区别于教学版）
- 沿用 `teacher.target_class_high1/2/3`：每学段一个行政班号。高二开学设 `target_class_high2 = 新行政班号`。
- **不引入** 教学版的 `teaching_class` / `class_label` / 走班抽象。班级标识仍是单一行政班数字。

### D2 · 跨学年身份：姓名确认为主 + 对照表为辅
- 库里**无**可自动认人的稳定唯一字段。**实测**：`SubjectScore.xueji` 只有 `1/3/4` 三个值、全体共用，是**学籍状态/类别码**，非身份键。`student_id` 即会随分班变化的校内学号。
- 因此跨学年链接：
  - **主路径**：换届向导按**姓名**去高一记录找候选，老师**逐个确认**「是我高一的某某 / 是新学生」。候选附**高一行政班 + 最近主三门名次/学号**帮助辨认同名。
  - **辅路径**：若学校能给「高一学号 ↔ 高二学号」对照表（Excel/CSV），一次性导入批量建链。
  - **绝不**按姓名自动并档（同名会错并档案）；链接只来自老师确认或对照表。
- 预留 `student_identity.ext_key`：若日后确认本校成绩表带身份证号/全国学籍号（G 开头），可作可选自动锚点，**默认不依赖**。

### D3 · 升级换届向导：一次性把高一名册结转到高二
- 高二开学（或首次上传高二成绩后）走一次向导，对**高二名册每个学生**判定四态之一：
  - `继承(inherited)`：已与某高一学号建链（对照表/已确认）→ 高一成绩、档案、作业自动接续。
  - `同名待确认(ambiguous)`：姓名命中一个或多个高一候选，老师确认是否同一人。
  - `新建(new)`：高一无记录 → 从高二起建档；附「导入高一成绩 / 手动关联高一学号」入口。
  - `未匹配(unmatched)`：来自花名册但成绩库还没有该学号的任何数据 → 待补。
- 同时把**作业花名册**（`class_roster`）结转到高二班（新学号、座号、性别）。

### D4 · 单年分析口径完全不动（零回归）
- 关注名单 / 段位分布 / 考试详情 / 班级对比 / 段位趋势 / 排名筛选 —— **都不解析身份**，仍按当年 `class_num` 过滤。年级内学号本就稳定，零成本零回归。
- **只有**「以学生为中心、需要跨学年连续」的读侧才解析人：学生画像/趋势、学生页的档案与作业、学生检索去重。

### D5 · 导入的高一成绩严格隔离
- 新转入学生导入的高一成绩，**单独存**（`imported_history`，按 identity 挂），只供**该生历史趋势展示**。
- **绝不**进入任何全年级排名 / 班均分 / 段位计算——它来自别的学校/班级的旧cohort，口径不可混。

### D6 · 错链可逆
- 提供「解除关联」：删 alias，把学号还原为独立人。继承关系随之撤销。

## 3. 核心概念模型

```
事实层（不变，照搬现状）：
   SubjectScore / TotalScore   按 (exam_id, student_id) 存
   高一考试 → 高一学号 + 高一 class_num
   高二考试 → 高二学号 + 高二 class_num      （Excel 本来就这么给）

身份层（新增）：
   StudentIdentity (人, 跨学段)
        └── StudentAlias (学号, 每学段一个) ──▶ 指回事实层的 student_id

班主任范围（不变）：
   teacher.target_class_highN = 我带的行政班号（每学段一个）
   单年分析： WHERE SubjectScore.class_num == target_class_highN   ← 照旧

跨学年学生视图（改造）：
   ids = person_ids(student_id)            # 同一人的全部学段学号
   画像/趋势/档案/作业读： WHERE student_id IN ids
```

**关键转译**：现有 `get_student` 等「以学生为中心」端点里的 `TotalScore.student_id == student_id`
→ 改成 `student_id.in_(person_ids(student_id))`。其余端点一律不动。

## 4. 关键假设与待验证项（执行 Phase 0 时确认）

| 假设 | 说明 | 验证方式 |
|------|------|----------|
| A1 | 跨学年**无稳定唯一字段**可自动认人；`xueji` 是 1/3/4 状态码 | 已由教学版 06 实测确认；执行时再 `SELECT DISTINCT xueji` 复核本库 |
| A2 | 高二成绩表自带**高二学号 + 高二 class_num**（与高一独立） | 拿真实高二样表确认学号列与高一不同段、班号列为高二班 |
| A3 | 班主任**多数沿班升年级**：高一(N)班学生大部分留在我高二班 | 决定向导默认把「高二名册∩高一已有姓名」预判为 `继承候选` |
| A4 | 高二名册可能**先于高二成绩**确定（开学排班，月考还没考） | 名册来源需支持「成绩派生」与「Excel/手工花名册」两路（新生此时无任何成绩） |
| A5 | 转入生的高一成绩来自**外校/外班**，cohort 与本校高一不同 | 强制隔离存储（D5），不进全年级口径 |
| A6 | 可能存在**同名**学生 | 向导 `ambiguous` 必须人工消歧，绝不自动链接（D2） |

## 5. 不改动的部分（保持现状，降低风险）

- 上传两段式流程（preview/commit）、文件名解析、考试建档、Excel 解析 schema（高一固定列 / 高二三 3+3）。
- 跨学年趋势的**指标选择规则**（主三门/语数英原始分；总分用 `xueji_rank`；+3 用等级分；`raw_score` 只作单点描述）——见源 `chat/session.py` 业务口径，照搬。
- 段位阈值 `analysis_config`（单行）与 `get_band_config()` 统一读取；段位排名仍是**全年级**口径。
- 单年所有分析端点、对比页、作业看板的内部计算逻辑。
- 部署 / 鉴权 / 数据目录 / 备份机制。
